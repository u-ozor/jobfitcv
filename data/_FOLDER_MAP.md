# data/

All personal/generated data. Entirely gitignored except this file and `templates/`.

| Path | What | Required for a fresh setup? |
|------|------|------------------------------|
| `resume_chunks.json` | Source of truth for all resume content — one bullet per entry | Yes — author your own, or start from `templates/resume_chunks.template.json` |
| `resume_embeddings.npy` + `resume_embedding_ids.json` | Paired embedding vectors for every chunk, generated from `resume_chunks.json` | Auto-generated by `scripts/embed_resume.py` — never hand-edit |
| `user_profile.json` | Contact info (name, email, phone, LinkedIn, GitHub) used for DOM form-fill only | Yes — author your own, or start from `templates/user_profile.template.json` |
| `job_targets.json` | Short role-type phrases for the role-match badge (display only, no effect on generation) | Yes — your own list, or start from `templates/job_targets.template.json` |
| `jobs.db` | SQLite DB — ingested jobs, variants | Auto-created by `app/database/init_db.py` |
| `taxonomy/*.npy` | One embedding per track (soc, sysadmin, backend, cloud, it_support, ai) used to classify incoming job postings | Ships with the repo |
| `templates/*.template.json` | Placeholder-content starter files for onboarding — consumed by `scripts/setup_wizard.py` | N/A — these are the templates |
| `chunks_backup/` | Auto-generated timestamped backups, written on every wizard save (last 10 kept) | No — safe to clear anytime |

See `docs/CHUNK_REVIEW_SPEC.md` for the full chunk schema, and the root `CLAUDE.md` for the intent behind each field.
